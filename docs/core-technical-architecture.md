# 心绪 · 核心技术方案

日期：2026-09-24  
状态：首版已按此方案收敛实现原型；供应商配置、正式安全审阅和身份鉴权待完成
依据：[产品设计总纲](product-design.md)；用户提供的两张技术框架截图仅作为候选技术清单，不作为实施指令。

## 1. 技术目标与范围

首版验证一件事：用户在情绪波动时，能便捷、可信地表达，获得合适的 AI 回应，并自主选择下一步。技术只服务于“信任 → 探索 → 安抚 → 行动”这条闭环。

**首版必须具备**：文字表达与现有日记入口、简明阶段管理、单一 AI 对话服务、少量人工审定的支持策略、独立风险拦截、用户可控的最小记忆、简短的前后自评。现有沙盘可继续作为独立表达入口；AI 与沙盘内容如何连接，需单独设计。

**首版暂缓**：多智能体、模型路由、向量检索/RAG、自动读取手表或微信运动、语音情绪识别、PHQ-9/GAD-7 自动评分、多种完整治疗流派模拟、自动联系亲友、社交账号绑定。暂缓不等于否定需求；先验证相应价值与安全条件。

## 2. 最小架构

```text
浏览器页面（现有 HTML/JS）
  ├─ 表达：文字、情绪日记；沙盘独立保留
  ├─ 用户控制：同意、策略选择、记忆查看/清除、行动确认
  └─ 本机数据：现有日记和沙盘；可选的会话摘要/偏好
             │ 用户发起且知情的 AI 请求
             ▼
单一 Python/FastAPI 同源服务（server/assist.py）
  ├─ 请求校验、频率限制、最少化上下文
  ├─ 安全层：输入检查 → 高风险分流 → 输出检查
  ├─ 会话编排：阶段、目标、用户偏好、策略卡
  └─ 模型适配：调用一个经评估的语言模型
             │
             ▼
模型服务（由环境变量配置；缺少实际数据告知则禁用）
```

浏览器不保存模型密钥。现有本地口令只用于 demo 的本机入口，不能作为后端身份认证。引入云端模型时，应通过同源 HTTPS 页面与后端通信，后端负责密钥、成本与滥用控制；是否需要正式账号和云端数据库，取决于跨设备同步需求，首版不预设。

## 3. 核心请求与数据流

一次 `POST /assist` 建议只包含：用户本次输入、用户选择的本次目标、可选的当前会话摘要、用户明确允许使用的长期偏好，以及前端已知的阶段。默认不传全部历史日记、沙盘作品、联系人或设备数据。

后端顺序：校验请求 → 安全层判断当前输入 → 在允许范围内确定阶段与支持策略 → 构造受约束的模型请求 → 检查模型输出 → 返回回复、当前策略说明、可选行动和安全状态。用户选择的行动由前端单独保存或分享；模型输出不能直接触发外部发送。

**关键数据对象（概念级）**：

| 对象 | 最小字段 | 保存与控制 |
|---|---|---|
| 会话状态 | 本次目标、阶段、用户明确偏好、最近必要上下文 | 首版优先本机会话；用户可结束和清除 |
| 长期偏好 | 称呼、喜欢/不喜欢的回应方式、已确认的有效方法 | 经用户确认后保存；可查看、修改、清除 |
| 用户记录 | 日记、沙盘、用户自评 | 维持现有本机存储；发送给 AI 前逐项告知并选择 |
| 安全事件 | 风险级别、触发类别、展示的求助路径 | 原则上不存原文；是否需要最小审计记录待隐私和安全设计确定 |

首版建议后端默认不持久化对话正文；必要的运营与故障日志不记录敏感原文。模型供应商是否保存请求、保留多久、是否用于训练，需要在接入前核查并写入用户说明；“本地保存”只能用于确实留在本机的数据。

## 4. 四阶段的技术实现

| 阶段 | 实现方式 | 为什么这样收敛 |
|---|---|---|
| 信任 | 复用现有首次进入与安全须知；AI 上线时增加真实数据流说明和独立授权 | 先保证承诺与实际处理一致 |
| 探索 | 文字输入 + 2–3 个可跳过的关键问题：当下感受、触发情境、本次想得到的帮助；AI 生成可纠正的理解摘要 | 不建复杂信息采集表，也不强迫用户选预设标签 |
| 安抚 | 单一模型 + 版本化系统规则 + 少量策略卡；用户可说“只听我说/换种方式/停止建议” | 验证回应质量后再扩展流派和人格 |
| 行动 | 从人工审定的行动类型中，由 AI 给出 1–3 个与用户目标匹配的选项；前端让用户编辑或拒绝 | 限制泛化和不切实际的建议；不让模型直接执行动作 |

**阶段管理**：代码保存 `explore | soothe | act` 和本次目标；信任是贯穿条件，不当作模型标签。模型可以建议切换，但最终由简单规则和用户明示意愿决定。允许随时返回前一阶段；不训练专门的阶段分类器。

**策略卡**：首版控制在 3–4 类可观察的支持动作，例如倾听与复述、当下稳定练习、想法与事实的区分、小步行动。每张卡写明适用目标、禁忌提示、一次只做什么、失败时如何退出。心理学流派名称保留在内部参考，不向用户宣称 AI 正在进行 CBT、精神动力学治疗或其他专业治疗。后续是否扩展需专业评审和用户验证。

## 5. 独立安全层

安全层独立于主对话提示词。它至少处理三件事：用户明确的高风险表达、模型回复中的不当建议、可用的现实求助路径。现有本地关键词提醒可作为原型提示，不能被当作生产级危机识别能力。

**首版流程**：规则识别明确高风险语句 → 对含糊情境做上下文复核 → 高风险时暂停常规策略并展示简短求助选择 → 生成后检查回复是否包含诊断、保证疗效、危险建议或未经同意的外部联系。规则与提示都要有版本；高风险样例和误报样例需由专业人员审阅。不能宣称零漏报或持续人工监护。

风险分流只改变本次回应与求助提示，不自动通知联系人。用户主动提出找真人时，优先协助其找到合适资源。热线、地区和服务时间需有人负责核实和更新。

## 6. 轻量效果观察

首版只收集用户自愿提供的简单反馈：开始与结束时的主观困扰程度（例如 0–10）、是否觉得被理解、建议是否有帮助，以及“没有帮助/让我更难受”的反馈入口。可显示用户自己的记录趋势，但不把数值变化解释为临床改善。

PHQ-9、GAD-7 等筛查量表不作为日常被动评分或自动诊断工具；若未来使用，需要单独确定目的、解释方式和专业支持路径。音乐、运动、思维导图等行动形式可以从现有内容逐步添加，先验证用户是否愿意采用和实际感受。

## 7. 取舍与后续扩展条件

| 技术候选（来自参考图） | 首版决定 | 重新考虑的触发条件 |
|---|---|---|
| ESConv、MAGIC 等策略数据或复杂策略库 | 暂缓直接接入；先用小型人工审定策略卡 | 基础策略已验证，且有明确版权、适配与评估方案 |
| RAG / 向量库 | 暂缓；少量可信内容用版本化配置 | 内容规模和更新频率使人工维护不可控 |
| 多模型路由、多智能体 | 暂缓；一个模型和一个编排服务 | 单模型明确达不到质量、成本或延迟目标，且有对照数据 |
| 独立安全分类模型 | 先用独立规则层和人工审阅样例；视评估结果加入 | 含糊风险的漏报/误报无法用规则控制 |
| PHQ-9/GAD-7、表情或语音识别 | 暂缓 | 明确用户价值、专业解释能力、授权及风险处理后 |
| 穿戴设备、微信运动、社交账号 | 暂缓 | 用户明确需要，平台接口可行且隐私方案可审查 |

**实施顺序建议**：① 先明确云端模型的数据处理与告知；② 打通文字对话、阶段控制和独立安全层；③ 加入可确认的记忆与行动选择；④ 在小范围用户研究中评估质量和风险；⑤ 再决定是否接入沙盘、语音或外部数据。

## 8. 待确认的架构决策

1. 首版 AI 是否调用云端模型？若是，用户数据能发送给哪类供应商，是否允许供应商保留请求？
2. 首版是否需要跨设备同步？这决定是否引入正式账号、数据库与服务端删除能力。
3. 现有“本地注册 + 强制须知”是否适合情绪波动时的快速进入？需要用真实用户验证。
4. 首版沙盘与 AI 是否打通？若打通，是用户自行描述作品，还是传递图像/结构化摆放信息？
5. 谁负责审核支持策略、风险样例及求助资源，并在上线后维护？

## 9. 依据与限制

- [OWASP 对浏览器端敏感信息暴露的说明](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/01-Information_Gathering/05-Review_Web_Page_Content_for_Information_Leakage/)支持将模型密钥留在服务端。
- [WHO 生成式 AI 健康治理指南](https://www.who.int/publications/i/item/9789240084759)强调健康场景中的安全与治理；本文的分层方案是基于产品需求作出的工程推论，并非 WHO 对具体架构的认证。
- [NHS England 心理治疗服务标准](https://www.england.nhs.uk/mental-health/adults/nhs-talking-therapies/service-standards/)将 PHQ-9 与 GAD-7 用作服务中的症状测量；首版不自动评分是产品范围和风险控制决策。
- 此方案尚未选定模型供应商、部署地区、数据处理合同或具体后端框架；相关选择需要与真实上线环境一起确认。
