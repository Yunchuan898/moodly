# 心绪 · 产品项目提交摘要

日期：2026-09-24  
用途：供 Vibe Coding 作业或比赛评审快速理解项目；此文件描述产品与原型，不代替完整设计文档。目前未取得本次作业或比赛的正式题目与评分标准，具体提交格式应以主办方要求为准。

## 一句话

心绪探索在年轻人发生日常情绪波动时，提供低负担的表达、整理和自主行动入口。

## 用户与问题

目标用户暂定为 18–27 岁的学生、研究生和职场新人。用户可能需要及时表达与安抚，也希望回看情绪变化、理解触发情境；正式咨询的预约、时间和费用在部分情境下构成门槛。该人群划分和痛点来自产品假设，仍需访谈验证，不能推断所有目标用户都有相同需求。

## 产品方案

长期设计按 **信任 → 探索 → 安抚 → 行动** 组织。用户应知道数据如何处理，能自由表达并纠正 AI 的理解，能查看或清除记忆，自主决定是否采取建议。沙盘作为不想打字时的表达选项，不自动解释作品或给作品打分。

当前原型已实现情绪日记、回看、自助工具、沙盘，以及统一交流页中的四目标按钮、有限策略、可控记忆和行动建议。AI 对话需要真实模型与供应商数据告知配置；未配置时页面禁止发送。安全规则仍是演示实现，不能把原型描述为 AI 心理咨询或完整危机干预。

## 演示路径

1. 按[仓库首页说明](../README.md#快速体验)启动同源 Python 服务，打开 `index.html`。
2. 记录一次心情，查看历史与自我关怀入口。
3. 从主页的沙盘入口进入，摆放沙具并保存作品；如愿意，可关联日记。返回后仍停留在主页。
4. 从主页的交流入口进入，直接点一个本次目标，查看数据告知和可选上下文；配置真实服务后可演示 AI 交流、记忆确认和行动建议。
5. 在主页设置中查看、修改或清除长期记忆，撤销 AI 授权，或明确退出当前会话。

演示可使用虚构内容。日记、沙盘和记忆保存在浏览器；AI 交流会按告知发往模型服务。当前原型不能提供专业判断或危机监护。

## 产品与技术取舍

| 决策 | 理由 |
|---|---|
| 保留日记与沙盘两种表达 | 让文字与非语言表达服务同一需求，检验哪种方式降低表达负担 |
| 首版 AI 规划收敛为单模型、少量审定策略 | 先验证被理解感、可控性和安全性，再评估复杂编排的价值 |
| 延后穿戴设备、自动量表、社交账号绑定 | 当前尚无足够用户价值证据，且增加授权、解释与维护成本 |
| 明确原型和产品承诺的边界 | 防止把本地关键词提醒、规则推荐或未经验证的分析当作治疗能力 |

技术细节见[核心技术方案](core-technical-architecture.md)；为何做这些取舍见[产品设计总纲](product-design.md)。
