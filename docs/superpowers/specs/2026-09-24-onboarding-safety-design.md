# 心绪 · 首次进入与安全须知 设计规格

> 状态：本地功能分支的 demo 规格；GitHub `main` 尚未包含该实现，正式产品安全能力仍待设计与验证
> 日期：2026-09-24
> 上游依据：`docs/product-design.md` 第 4 节设计原则、第 9 节数据隐私与安全、第 12 节待讨论决策 5
> 当前评审：`docs/implementation-audit-2026-09-24.md`；该文档的“已实现”仅指本地演示代码

## 1. 要解决的问题

心绪当前打开即用，没有身份、没有知情同意、没有安全边界说明。这在产品上是三个缺口：

1. 用户不知道自己的数据存在哪、谁能看到。
2. 用户不知道这个工具的边界——它不做诊断、不做治疗、不替代专业帮助。
3. 当用户表达出强烈痛苦时，产品没有任何回应方式。

本规格定义首次进入流程、安全须知正文，以及风险识别与提醒的最小实现。

## 2. 一个必须先说清的立场

心绪不是心理咨询师。它没有能力「采取安全措施」，也不具备保密协议的法律主体地位。直接照搬咨询知情同意书的措辞，会让用户误以为自己在和专业服务建立关系——这违反产品设计总纲第 3 节的边界：「不把自我关怀工具包装成专业治疗服务」。

所以本设计写的是**「这个工具能做什么、不能做什么、什么时候必须去找真人」**，而不是「我们有权对你采取措施」。

由此推出一个必须诚实处理的矛盾：**纯本地架构下，本地页面脚本能处理用户写的内容，但服务端无法持续监测并主动联系紧急联系人；「严重时联系紧急联系人」这一条在当前版本不可能真正生效。** 直接写成承诺就是撒谎。处理方式是在须知第 4 节打明确标记，说明该条在具备相应服务能力的后续版本才可能生效。

## 3. 已确认的决策

| 议题 | 决策 | 依据 |
|---|---|---|
| 登录定位 | 本地身份 + 为云端留位。口令本地加盐哈希，明确告知「这不是安全防护，换设备就没了」 | 与「首版仅本地保存」的假设一致，不引入后端 |
| 账号标识 | 昵称 + 口令 | 最小可用；邮箱/手机号留给云端版 |
| 最信任的人 | 仅在「安全与支持」面板由用户主动查看，全站其他位置不出现 | 不在用户脆弱时替用户决定要不要联系谁 |
| 须知呈现 | 首次一次性阅读 + 滚动到底 + 勾选同意；之后可随时回看 | 知情同意必须可回溯，但不做成每次打扰 |
| 危机处理 | demo 实现：命中风险信号 → 弹温和提醒（热线 + 手动联系入口），**绝不自动发送任何东西** | 自动发送需要后端、需要准确判定、且不可撤回，超出 demo 范围 |
| 风险判定 | 分级词表 + 强度/频率升级；单一弱信号不触发 | 误报毁掉的是信任本身 |
| 通知内容 | 若将来实现，仅告知「此人存在心理风险，请求协助」，不输出任何具体记录内容 | 与保密原则一致；用户才不会因为怕被看而不敢写真话 |
| 测试框架 | demo 不引入。`assess()` 设计为纯函数，将来可直接加测试 | 现有工程无构建工具与 package.json |

## 4. 模块划分

现有结构：`index.html`（情绪日记，内联脚本）、`sandbox.html`（沙盘，引入 `src/sand|shelf|scene|witness.js`）。

新增五个模块。拆分的依据是**改文案时不用碰识别逻辑，改识别逻辑时不用碰文案**：

| 文件 | 职责 | 依赖 |
|---|---|---|
| `src/safety-content.js` | 纯数据：须知正文、求助热线、风险词表 | 无 |
| `src/vault.js` | 本地存储层：账号、同意记录、联系人档案的读写 | safety-content（比对须知版本） |
| `src/safety.js` | 纯逻辑：`assess(text, ctx)` 返回风险等级；命中时弹提醒 | safety-content, vault |
| `src/support.js` | 「安全与支持」面板：联系人、热线、重读须知、清除数据 | vault, safety-content, onboarding |
| `src/onboarding.js` | 首次引导三步遮罩 UI；导出 `renderNoticeInto()` 供 support 复用 | vault, safety-content |

`onboarding.js` 导出须知渲染函数给 `support.js` 使用，避免须知正文出现两份、两处措辞不一致。依赖方向单向，无循环。

## 5. 本地数据结构

沿用现有 `xinxu.` 前缀命名。

```
xinxu.account.v1  { nickname, salt, passHash, trustedContact:{name,relation,phone}, createdAt }
xinxu.consent.v1  { noticeVersion, agreedAt }
xinxu.safety.lastPrompt.v1  { date }        // 提醒冷却，同日不重复弹
```

口令处理：`crypto.getRandomValues` 生成 16 字节 salt，`crypto.subtle.digest('SHA-256', salt + '|' + pass)`。在非安全上下文（部分浏览器的 `file://`）`crypto.subtle` 不可用，降级到 FNV-1a 并加前缀标记。

**代码注释中必须写明：这不是安全防护。** 同一台设备上任何人都能用开发者工具读到本地数据。它的唯一作用是避免明文口令落盘。

## 6. 首次进入流程

`<head>` 中放置一段同步检查脚本，未完成引导时给 `<html>` 加 `xo-pending` 类，配合 CSS 隐藏 `body`，避免页面内容在遮罩出现前闪现。`onboarding.js` 完成引导后移除该类。

三步遮罩，不可跳过。页面加载时按当前状态决定挂哪几步：

1. **注册 / 登录** — 昵称 + 口令。**每次进入都要过这道门**；没有账号时是注册，有账号时是登录。登录页附「忘记口令？」，点开说明本地无法找回，只能清除本机全部数据，需输入「清空」二次确认。本地没有找回途径，必须诚实提供出口，否则用户会被自己的数据锁在门外。
2. **安全须知** — 只在首次（或须知版本变更后）出现。正文需滚动到底，勾选框才解锁。
3. **最信任的人** — 只在首次出现，可「暂时不填」。跳过就不再追问，未填时由「安全与支持」面板持续提醒。

完成后写入 `account.v1` 与 `consent.v1`（记录 `noticeVersion`）。**须知版本变更时 `hasConsented()` 返回假，用户会被重新要求同意**——这是知情同意应有的行为。

## 7. 须知正文

六节，语气遵循总纲第 4 节「温和而具体，不评价、不说教」：

1. 心绪是什么
2. 心绪不是什么（含求助热线）
3. 保密原则
4. 保密例外（含云端版生效标记）
5. 你的权利
6. 数据归属

## 8. 风险识别与提醒

`assess(text, { intensity, recentEntries })` 返回 `{ level, reasons }`，`level` 取 `none | elevated | urgent`。

**分级词表**：
- 强信号词（自伤、自杀、割腕、遗书、活不下去等）命中即 `urgent`。
- 弱信号词（绝望、撑不下去、崩溃、解脱等）需叠加条件才升级：同一条命中 ≥2 个，或命中 1 个且情绪强度拉满，或命中 1 个且近期连续多日情绪极低。
- 单一弱信号不触发。这是刻意的：**误报毁掉的是信任，一个人被产品背刺过一次，就再也不会在里面写真话了。**

**必须处理的误报**：中文里「死」大量用于夸张（笑死、累死、饿死、热死、烦死、气死、吓死、困死）。匹配时排除「夸张词 + 死」的组合。

**提醒弹层**：措辞不判定、不说教。展示求助热线、用户预留的联系人、「我自己联系」（唤起 `tel:` / `sms:`）与「我没事」。关闭后写入冷却日期，同日不再弹。

**绝不自动发送任何东西。** 无论等级多高，是否联系由用户自己按下。

## 9. 安全与支持面板

顶栏常驻入口，`index.html` 与 `sandbox.html` 都有。内容：联系人档案（可编辑）、求助热线（`tel:` 链接）、重读安全须知、清除全部数据（二次确认）。

## 10. 边界与不做的事

- 不做云端账号、不做数据同步、不做任何联网请求。
- 不做自动通知。demo 中该条款仅作为须知内容呈现。
- 不做心理状态判定、不做诊断、不做分级标签展示给用户。
- 不做使用提醒、不做打卡压力。
- 不引入测试框架与构建工具。

## 11. 实现与验证

实现时产生的一处决策变更：**登录门每次进入都出现，不只是首次。** 原规格写的是"首次进入有注册登录"，但既然数据全在本地，把入口锁上才让"登录"有实际含义——它能挡住随手拿起你手机的人，挡不住懂技术的人，文案上如实说明即可。

验证方式：用 headless Chrome 真实加载页面跑断言（本工程无 Node.js 与测试框架，测试页用完即删，未留在仓库里）。

| 范围 | 条数 | 结果 |
|---|---|---|
| `assess()` 与 `lowStreak()` 纯逻辑 | 19 | 全过 |
| `vault` 存取、口令、清空 | 12 | 全过 |
| 完整引导流程、支持面板、重读须知、二次确认、登录门 | 35 | 全过 |
| `index.html` 保存日记 → 触发提醒的端到端链路 | 14 | 全过 |
| 两个真实页面加载与顶栏绑定、控制台无报错 | — | 通过 |

覆盖到的关键行为：`xo-pending` 在引导完成前隐藏页面且完成后摘除；须知不滚到底勾选框禁用；「笑死我了」「烦死了」「想死你了」均不误报；「我不想活了」在低强度下也升级；同日不重复打扰；口令错误不放行且不泄露信息。

**未验证**：真机上的触摸与滚动体验、`tel:` 链接在手机上的实际拨号行为、字号与窄屏布局。这些需要人在真实设备上看一遍。
