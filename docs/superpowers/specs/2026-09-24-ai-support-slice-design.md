# 心绪 · AI 支持独立切片设计

日期：2026-09-24
状态：可合并的本地演示实现；不代表临床或正式上线能力。

## 目标与边界

实现一条可独立体验的“探索 → 安抚 → 行动”链路：用户选本次目标并自由输入；后端从有限、可解释的策略中选择支持方式；模型给出简短回应；系统提供与本次目标相符的可编辑行动选项。长期记忆只在用户主动保存后存在，并可查看、修改、删除。AI 数据发送前展示供应商、数据范围和保留说明并取得单独确认。

另一位开发者负责对话分析和穿戴设备接口。本切片不改 `assist.html`、`src/agent.js`、`src/wearables.js`、现有页面或原有本地登录/安全模块；通过 HTTP 协议留出可选的分析提示。穿戴信息不进入本切片。

## 目录与运行

全部新实现放在 `ai-support/`，使用 Node 20+ 标准库和原生浏览器 JS。`server.mjs` 同源提供演示页面及 `/api/support/*`，服务默认只监听 `127.0.0.1`。模型调用走服务端配置的 Chat Completions 兼容接口，浏览器不接触密钥；没有配置模型及真实供应商告知时，拒绝 AI 请求，不用假回复冒充模型。

## 请求协议

`POST /api/support/respond` 接收 JSON：

```json
{
  "consent": true,
  "consentVersion": "ai-support-v1",
  "message": "今天和同学吵架了，心里很乱",
  "goal": "understand",
  "phase": "explore",
  "style": "warm",
  "history": [{ "role": "user", "content": "..." }],
  "memory": ["用户主动确认保存的偏好"],
  "analysis": { "strategyHint": "reflect" }
}
```

`goal` 只能为 `be_heard | understand | calm | next_step`；`phase` 只能为 `explore | soothe | act`；`style` 只能为 `warm | direct`。`analysis.strategyHint` 仅接受枚举值，且用户明确选择的目标优先。服务端重新校验长度、数量和枚举，不相信浏览器或分析器传来的指令。返回 `reply`、可纠正的 `understanding`、`phase`、`strategy`、`actions`、待用户确认的 `memoryCandidate` 和 `safety`。行动只能从与目标匹配的审定目录选取，模型不得发起联系、写入记忆或执行外部动作。

## 策略与失败处理

策略分别为倾听复述、探索澄清、当下稳定、想法梳理、小步行动。服务端以用户目标和阶段选择；分析提示只有在允许集合内才可细调。模型回应不得下诊断、保证效果或模仿治疗师。模型输出必须是 JSON；解析或字段校验失败时返回明确错误和重试提示，不伪造“AI 已理解”。

演示页直接显示四个目标按钮：先听我说、一起梳理、让我缓一缓、想想下一步。页面根据目标生成阶段，默认使用温和回应；不要求用户先理解内部阶段或策略名称。“先听我说”不显示行动建议。记忆与清除操作放在可展开区域，发送前的数据告知仍保持可见。

独立输入规则拦截明确自伤/自杀信号并给现实求助路径，含糊语句仍可能漏报；输出规则拒绝明显诊断、疗效保证和危险建议。规则是演示性保护，不能宣称危机识别完整或有人工值守。高风险内容不发给模型；不自动联系任何人。超时、供应商失败、请求过长、频繁请求均给可理解的错误。

## 数据与告知

后端不写会话原文、记忆或行动到磁盘/数据库，不打印请求正文；每次模型调用只带本次输入、最多六条会话上下文和用户本次勾选允许发送的最多十条记忆。前端会话只在当前页面内存，关闭页面即消失；已确认记忆、AI 告知同意记录保存在当前浏览器 `localStorage`。本机清除按钮删除这两类数据；无法撤回已发送到模型供应商的请求，供应商保留和跨境处理须由部署者核实并明确告知。

`GET /api/support/info` 返回实际配置的供应商名称、隐私政策 URL、保留说明与告知版本。配置缺失时不允许发送。演示页必须先展示这些信息和数据范围，用户主动确认后才可请求。既有首页的“只在浏览器保存”须知只适用于首页原型，未来统一入口合并时必须改写；此切片不修改原页面以免与其他开发者冲突。

## 合并约定

对话分析器只输出可选 `strategyHint`，不要传提示词或任意策略文本。未来页面可调用同源 `/api/support/info` 与 `/api/support/respond`，自行管理用户授权状态、会话与已确认记忆。穿戴数据必须单独取得授权并另设字段及告知，不能悄悄并入 `history` 或 `memory`。
